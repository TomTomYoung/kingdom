# 戦術AI・増援戦と勝敗

確認日: 2026-10-30。開始基準: main / 78cd406（PR #6）。[現行実装](CURRENT_IMPLEMENTATION.md)・[操作](COMBAT_OPERATIONS.md)・[検証](STATUS.md)。

## 遊び方と範囲

「AIとの遭遇戦」を選び「新規開始」を押すと、人が黎明王国、AIが夕映王国を操作します。各国は1都市と戦士2・弓兵2・弩砲1の部隊を持ち、部隊位置は1,-1,0と6,-6,0です。接近用にq=1〜6の(q,-q,0)を平原にします。既存の開拓と二国交互操作は維持し、勝敗を後付けしません。

遭遇戦のAIは通常の遠隔・近接攻撃と移動を行います。「AIとの増援戦」は同じ配置・勝敗条件で、兵の生産・購入・編成も行います。都市建設、建物・領土の購入、範囲や狙い撃ちの選択、配置・護衛の再設定、撤退、戦略評価は後続です。人は既存の都市操作・編成・7攻撃を使えます。対等な都市運営AIや完成した難易度調整ではありません。

## 決定論と手番

`AIController.nextCommand`は状態を変更せず、次のRNGも読みません。ID順の自軍・敵軍から即時の通常遠隔攻撃、できなければ近接攻撃を探します。攻撃がなければ地形費を使うDijkstraで合法な射程位置への経路を求め、当ターンの移動力内の接頭経路を選びます。Voidと他の活動部隊を避け、敗北記録は占有しません。民間Unitだけの部隊を攻撃のために移動させません。

選択したCommandは全てRuleSystemで検証・実行します。移動・攻撃と、増援戦では補充の合法な候補がなくなればEndTurnです。通常命令は最大128回、その後はEndTurnを強制し、行動不能でも手番が進みます。coreの`runAiTurn`は呼出しごとの上限、UIは同一王国・同一ターンの保存済み命令数を使います。命令失敗はループせず停止し、UIに理由と再開ボタンを表示します。

UIは約180msごとに1命令を適用します。人の表示国・都市・選択を保持し、自軍の変更操作を止めます。地図・戦闘ログの閲覧とセーブは可能です。ロードでAI手番を自動再開し、新規開始・別保存のロード・ページ離脱時は旧タイマーを取り消します。タイマーや表示選択はGameStateに保存しません。

## 都市生産・購入・増援

増援戦はkingdomの`aiPolicy: 'reinforcements'`で有効化します。省略または`tactical`は都市増援を行いません。新規partyRecoveryVersion 1は休養・離脱も判断します。新規の増援戦だけに設定するため、旧遭遇戦のセーブ・行動列は変わりません。AI専用の資源付与はなく、SetCityProduction／PurchaseCityItem／CreateParty／ReinforceParty／MergeParties／MovePartyを共通RuleSystemで実行します。

判断順は、合法な都市占領、新規版での安全な離脱・休養、既存部隊への補充、都市出口の確保、待機兵の編成、即時攻撃、小部隊の合流、接近移動、生産設定、購入、手番終了です。待機兵がいるか購入可能な都市を自軍部隊が塞ぐ場合、合法な到達先へ移動して中心を空けます。移動先は都市以外のセルとし、戦闘部隊は敵に近い側、民間だけの部隊は遠い側を優先します。敵の占有、移動力切れ、行動終了、通路なしなら無理に動かさず、手番を進めます。

待機兵は同じセルのHP>0・active・非民間UnitをID順で最大5体まで編成します。1体でも部隊を作り、既存部隊の生存Unitを引き抜きません。増援も通常の移動・攻撃を行います。既存の戦闘部隊と同じセルの待機兵は先に空き枠へ補充します。即時攻撃がなければ、非民間だけの隣接部隊を最大5体まで合流します。人数の多い部隊を合流先、少ない部隊を合流元として、同数ならID順で合法な組を選びます。両操作は当ターンの関係部隊の行動・反応を終了します。自動分割はありません。[再編規則](PARTY_MANAGEMENT.md)。

兵種は戦士:弓兵:弩砲=2:2:1を目安に、王国全体の生存兵＋生産中・予約中の兵が少ない種類を選びます。同率は戦士→弓兵→弩砲です。都市はID順で扱い、購入時はこの順から予算に収まる種類を選びます。次の暫定値はRuleset.aiRecruitmentにあります。

- 生存非民間Unit＋全都市の生産・予約中の非民間Unitが15体以上なら新規発注しません。既存の生産を取り消したり、超過したUnitを消したりはしません。
- 購入は全額Goldを払い、予備費24以上を残します。各都市・各ターンで最大1回です。購入履歴は保存済みCommandから判定するため、途中ロードで回数は復活しません。
- 生産は対象・キューが空の都市だけに設定します。既存の進捗・予約を維持します。敵部隊がいる都市や5体以上の待機兵がいる都市には発注せず、活動部隊が占有する都市で購入しません。

兵は通常のターン開始の生産処理で完成し、AI手番で編成します。資源・ID・生産進捗の直接更新は行いません。UIは直近のAI手番の生産設定・購入・増援編成・補充・合流・移動・攻撃の回数を表示します。

## 終了規則

遭遇戦・増援戦は共通の`scenarioObjective = { type: 'eliminate-parties', participantIds: ['kingdom-1', 'kingdom-2'], turnLimit: 40 }`を持ちます。期限は暫定値です。

- 活動中で生存Unitを含む部隊が片方の王国にしかなければ、その王国の勝利です。後から編成した部隊も含み、都市・未編成Unitは判定から除きます。
- 両国とも対象部隊がなければ引き分けです。
- 撃破による決着がなく40ターン目の両国手番が終われば引き分けです。41ターン目の収入・行動値回復の前に止めます。

成功Command後に判定するため、近接反撃による攻撃側の敗北も結果へ反映します。終了時は`phase = 'GAME_OVER'`とし、`gameResult`へoutcome（victory/draw）、winnerId（勝者またはnull）、reason（elimination/turn-limit）、turnを保持し、ScenarioFinishedを1回記録します。終了後の全Commandは元state・空eventsで拒否します。画面は勝利・敗北・引き分けを表示し、閲覧・保存・復元・新規開始を許可します。

これは全敵部隊撃破のScenario Objectiveです。別モードの都市争奪戦には都市占領・全都市支配を追加しました。首都喪失・降伏によるDomination全体、Dungeon Conquest、Scoreは実装していません。

## 都市争奪戦

「AIとの都市争奪戦」は増援戦と同じ配置・予算規則で、目標をcontrol-citiesにします。全都市を支配すると勝利、全都市を失うと敗北し、軍隊を失っても都市から再建できます。期限は40ターンです。王国・部隊・待機Unitの記録を削除せず、都市0の敗者も保存・表示できます。

AIはCaptureCityを最初に選び、新規版では安全な離脱・休養、その後は補充・都市出口・編成・即時攻撃・合流を判断します。新規対局では即時部隊攻撃と合流の間にAttackCityを選びます。接近は防御中の都市の射程内位置、破城後は空いた敵都市中心への地形費付き経路を優先し、経路がなければ敵部隊を目指します。経路があっても残り移動力で次セルへ入れない場合はその場で待ちます。都市中心に入るだけでは占領せず、共通Commandで攻撃回数を使い、所有権移管と勝敗を確定します。最後に生産設定・購入・手番終了を行います。

従来モードの目標とAI判断は変えません。人口・生産・領土・収入・待機Unitの扱い、保存条件、ブラウザ検証は[CITY_CONQUEST.md](CITY_CONQUEST.md)を参照してください。

## 保存互換と検証

目標と結果は組で保存し、参加国・期限・phase・生存部隊・勝者・終了理由・終了ターン・期限時の一巡を検証します。不正な勝者や未終了の全滅状態を拒否します。旧モードは目標と結果の両方がない状態を維持します。controllerTypeはhuman/aiを認め、旧保存の省略だけhumanへ補完します。aiPolicyは省略を維持し、存在する場合はtactical/reinforcementsだけを認めます。増援戦の識別子があるのにAIの増援方針がない保存は拒否します。

`tests/ai-scenario.test.js`は判断の不変性、RNG非参照、通常移動・攻撃・手番、迂回・占有・民間・行動上限、途中再開、勝利・敗北・反撃・期限、全Command拒否、保存の整合性、AI同士の対局完了を確認します。

旧増援戦の状態は復元できますが、reinforcements方針に補充・合流の選択を追加したため、旧版との将来の行動列一致は保証しません。現行版での保存前後の再開と、旧tactical方針の行動列は維持します。

`tests/ai-economy.test.js`は共有予算・予備費・兵種・予約枠・購入上限・都市占有・編成・増援戦闘・生産完了・旧AI保存の不変性と再開を確認します。

実ブラウザQAは任意の開発依存Playwrightを使います。ゲーム本体への依存は追加しません。

```sh
KINGDOM_QA_MODULES=/path/to/node_modules node tools/qa/browser-ai.mjs /tmp/kingdom-ai-qa
```

`KINGDOM_BROWSER`でChromium実行ファイルを指定できます。UIの手番・ロック・途中ロード・取消・3結果・不正保存・390px表示・交互操作に加え、増援戦の購入・編成・戦闘・生産・行動表示と途中再開を検証します。

都市耐久・城壁・自然修復の条件、旧都市争奪戦の版なし保存を維持する規則は[CITY_SIEGE.md](CITY_SIEGE.md)を参照してください。版2のAIは、敵軍が3ヘクス以内の都市に城壁を発注します。最低5生存兵と活動部隊を必要とし、予備費24・都市別1購入・既存の軍事生産キューを守ります。全軍再建を優先し、近接攻城での確実な全滅も予測で回避します。[詳細](CITY_RETALIATION.md)。旧版1では城壁の判断を追加しません。

## 新規対局の休養・戦闘不能者の離脱

partyRecoveryVersion 1では都市占領の次に、自軍PartyをID順で確認します。各Partyで合法なRemoveCasualties、次に生存UnitのいずれかがHP50%以下なら合法なRestPartyを選びます。両方とも一手番を使い、回復場所を求めた撤退は行いません。UIの行動一覧、同じCommandでの拒否・保存再開に対応します。版なし旧保存のAIには追加しません。[規則と互換](PARTY_RECOVERY.md)。
