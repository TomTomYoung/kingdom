# 都市占領と都市争奪戦

確認日: 2026-10-30。開始基準: PR #7 / fa0c260。[現行実装](CURRENT_IMPLEMENTATION.md)・[AI](AI_SCENARIOS.md)・[検証](STATUS.md)。

## 遊び方と終了条件

新規ゲームで「AIとの都市争奪戦」を選びます。人は黎明王国、AIは夕映王国です。初期配置は増援戦と同じで、各国1都市・戦士2・弓兵2・弩砲1の部隊を持ちます。都市の中心は0,0,0と4,-4,0、部隊は1,-1,0と6,-6,0です。

新規対局では先に[攻城](CITY_SIEGE.md)で城壁と都市耐久を0にします。その後、軍事Unitを含む部隊を敵都市の中心へ移動し、「都市占領」で確定します。敵部隊が中心にいれば通常戦闘で先に撃破します。移動だけでは所有権を変えません。占領は部隊の現在地が対象都市の中心である場合に限ります。中心を選んだだけの遠隔占領はできません。

このモードの目標は`control-cities`です。全都市を一国が支配するとその国が勝利します。最初の首都だけを失っても他の都市があれば続行でき、部隊が全滅しても都市の生産・購入から再建できます。最後の都市を失うと、部隊・待機Unitが残っていても即敗北します。理論上両国とも都市がない状態では引き分けです。40ターン目の両国手番終了で未決着なら、41ターン目の収入前に引き分けとします。

これは全都市支配のScenario Objectiveです。首都の特別扱い・降伏・政治的主権は未実装で、目標のDomination全体の完成ではありません。既存の遭遇戦・増援戦は`eliminate-parties`のままです。都市占領Commandは`control-cities`目標の対局でだけ使えます。

## CaptureCity

payloadは`{ partyId, cityId }`です。共通のCommand／RuleSystemから次を検証します。

- 自国の手番・PLAYER_ACTION・対局未終了で、都市支配目標があること。
- 対象が存在する敵都市であること。cityDefenseVersion 1／2では城壁・都市耐久とも0であること。版なし旧保存は耐久条件を追加しません。
- 自国のactive部隊で、HP>0・active・非民間の構成員を含むこと。戦士に限らず弓兵・弩砲も占領できます。民間だけの部隊や敗北記録は占領できません。
- 行動が未終了で攻撃回数1以上あり、現在地が都市中心であること。通常移動で移動力を使い切っていても占領できます。
- 中心を他のactive部隊が占有していないこと。敗北記録・未編成の待機Unitは活動部隊の占有として数えません。

成功すると占領部隊の移動力・攻撃回数・反応を0にしてended、hasAttackedをtrueにします。HP・護衛容量・配置・指揮者・士気・結束・Unitを変更しません。通常の無料近接反撃と肩代わりは従来規則のままで、反応0が止めるのは割り込みです。

## 都市と領土の移管

都市ID・名前・位置・人口・食料・地域文化・建物・産出補正を保持します。City.ownerIdを変え、旧国のcityIdsから除去し、新国のcityIds末尾へ追加します。その都市をterritoryCityIdに持つ全セルのownerIdを移します。都市中心・所属都市のIDは変えず、近隣の別都市の領土も移しません。

生産対象・予約・全進捗を解除し、返金しません。収集表示・作業セル・内訳を0／空へ戻し、前所有国の収入を新所有国の収入として表示しません。占領直後に収入・生産・成長・文化拡張を実行せず、次の全王国一巡後の開始処理から新所有国が一度ずつ収集します。占領後すぐに新所有国が生産を設定したり、全額を払って購入したりできます。両国の派生能力・統治負荷は占領時に更新します。

国庫・研究／王国文化・humanResourcesは移管しません。現行のhumanResourcesは都市人口との同値ではなく、今回人口から再算出しません。Unitの国籍・所属・位置・HPは全て保持します。中心にいた元所有国の待機Unitは残り、占領部隊がいる間は通常の占有制約で部隊化できません。捕虜化・徴用・自動避難・削除はありません。活動部隊が不在で、敵都市の防御も0なら、対局が続いている限り元所有国が通常のCreatePartyで編成できます。版なし旧ルールでは防御条件はありません。

新規対局の占領では耐久25・城壁0にし、最終被害ターンを記録します。城壁建物は保持します。版2では残る都市反撃回数を0にし、次の全体ターン開始で1に更新します。

CityCapturedにcityId、partyId、previousOwnerId、ownerId、territoryKeysを記録します。新しい都市や部隊のIDを発行せず、RNGも消費しません。拒否時は元stateと空eventsを返し、資源・ID・RNG・ログを変えません。最後の都市なら続けてScenarioFinishedを1回だけ記録します。

## AIと画面

都市争奪戦のAIは増援方針を使い、最初に可能な占領を探します。その後は補充・都市出口の確保・新部隊編成・即時攻撃・合流を既存規則で判断します。新規対局では即時攻撃の後、合流の前に攻城を選びます。接近時は防御中の敵都市の射程内位置、破城後は空いている敵都市中心への地形費付き最短経路を優先し、経路がなければ敵部隊への接近を使います。経路はあるが当ターンの残り移動力で次セルへ入れない場合はその位置で待ちます。守備隊を飛び越えたり、Voidを通過したりはしません。最後に生産設定・購入・手番終了を判断します。

自国の全活動部隊を失っても、都市がある間はAIが生産・購入・編成して再建できます。選択はRNGを読まず、全行動を共通Commandで実行します。従来の戦術AI・増援AIの行動列は変更しません。

画面には都市数・勝敗条件・占領対象と実行不可の理由を表示します。成功後は獲得都市を選び、都市切替・生産・購入・領土・地図へ反映します。AIによる都市占領回数も表示します。都市を全て失った側は「所有都市なし」を表示し、都市関連の操作を停止します。終了後も自国の資源・残存部隊・地図・記録を閲覧でき、保存・復元ができます。

## 保存と検証

新規モードのscenarioIdは`ai-conquest`、目標は`{ type: 'control-cities', participantIds: ['kingdom-1', 'kingdom-2'], turnLimit: 40 }`です。都市支配で終了したgameResult.reasonは`cities-controlled`、期限なら`turn-limit`です。王国やturnOrderは削除せず、都市0の敗者も保存します。

新規フィールドや旧保存への目標補完はありません。新モードと目標種別の不一致、未終了なのに片国の都市が0、偽の勝者・理由、所有権の部分移管を保存検証で拒否します。途中AI保存は移動後から同じ占領・勝敗へ再開します。既存保存の状態と旧AIの行動列は維持します。

`tests/city-capture.test.js`の19テストと、`tools/qa/browser-conquest.mjs`の実ブラウザ10チェック群で、移管・拒否・行動終了・駐留・収入・再占領・部隊再建・都市0の敗者・期限・再現性を確認します。

```sh
KINGDOM_QA_MODULES=/path/to/node_modules node tools/qa/browser-conquest.mjs /tmp/kingdom-conquest-qa
```
