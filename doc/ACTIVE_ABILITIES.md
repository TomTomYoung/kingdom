# 能動能力の最小実装

確認日: 2026-11-04。開始基準はmain / 0aebc09（PR #12マージ後）。名称・兵種への割当・費用・回復量は暫定です。正式な職業・呪文一覧や任意効果を実行する汎用エンジンの完成ではありません。

## 利用範囲と定義

新規の「AIとの増援戦」「AIとの都市争奪戦」だけにactiveAbilityVersion 2を付け、初期戦士と以後の生産・購入で完成した戦士へ治癒を付けます。他の既存モード、版のない旧対局へ自動的に能力を付けません。mana初期値0と霊脈の既存産出は変更しません。

版2では弓兵の[魔弾](MAGIC_ABILITIES.md)も使えます。以下の回復効果・費用・RNG不使用の説明は治癒のものです。版1の保存は治癒のみのまま維持します。

定義の正本は[src/core/abilities.js](../src/core/abilities.js)です。発動者は治癒を習得した戦士、対象は同じ活動中Partyの生存・活動中Unitです。自分自身・同行する開拓者も対象にできます。HP0・別Party・待機兵・敵Unitは対象外です。

- 回復量30、最大HPで打ち止め。
- 王国mana 4、Gold 0、Party移動力1、Party攻撃回数1、発動Unitの有限チャージ1を消費。
- 各発動Unitは初期3チャージ。全体ターン・休養・ロード・配置変更・合流・分割・補充では補充しません。チャージ0でもUnitは残ります。
- Unit.abilityStates.heal.usesRemainingは初期1、全体ターン開始に1へ戻します。戦闘不能記録の回数も戻りますが、HP・statusは保持し発動不可のままです。Unit.charges.healとは別の制限です。手番交代だけでは戻しません。
- 使用後はPartyの移動力を0、activationStateをendedにします。攻撃回数は定義費用分を減らします。反応回数・Guard容量・士気・忠誠・状態異常・Unitの旧行動欄は保持します。
- 発動者のstun／break／fear、行動終了・休養中、費用不足、HP満タンを拒否します。移動後でも移動力1と攻撃回数1が残れば発動できます。

## Commandと予測

UseAbilityのpayloadはpartyId、casterUnitId、abilityId、targetUnitIdの4つだけです。クライアントから倍率・回復量・費用・効果を受け取りません。HumanControllerとAIは同じCommandを発行し、RuleSystemが手番・フェーズ・重複ID・対局終了を先に検証します。

validateAbility、previewAbility、resolveAbilityを[実行処理](../src/systems/ability-system.js)へ分離しました。予測は検証を共有し、実回復量・回復後HP・費用・残チャージを返します。予測も実行も戦闘／領土RNGを読みません。失敗Commandは元の状態を返し、HP・国庫・回数・ID・ログ・RNGを変更しません。

回復はcurrentHpと互換hpを同時に更新します。manaを支払った直後に既存の軍事力表示を再計算します。manaを軍事力へ換算する式自体は変更しません。AbilityUsedに発動者・対象・部隊・能力・実回復量・回復後HP・費用・残チャージを記録します。

## 画面とAI

自国部隊の能力欄で発動者・能力・対象を選択し、費用・残り有限チャージ・この全体ターンの使用回数・回復予測・拒否理由を確認できます。選択だけではGameStateを変更せず、実行ボタンだけがCommandを発行します。AI手番・対局終了後は操作できません。ロード・新規開始で選択を初期化し、Unitが所属部隊から外れれば対象候補を更新します。キーボードでも選択・実行できます。新規画像・専用SEは追加せず、既存の確認音を使います。

AIは都市占領・都市砲撃・戦闘不能者離脱・安全な休養を先に検討します。その後、HP50%以下で合法な治癒対象があれば、HP比率の小ささ、実回復量の多さ、部隊／対象／発動者／能力ID順に選びます。乱数を読みません。安全に休養できるときはmanaと有限チャージを温存します。高度な被害予測や資源配分の最適化ではありません。

## 保存と互換

activeAbilityVersionは1と2を受理します。1は治癒のみ、2は魔弾にも対応します。新版ではabilityStatesとchargesを辞書として検証し、習得能力ごとに使用回数とチャージの対が必要です。既知能力・兵種・整数範囲・状態のキーを検証し、欠落した片方を補充しません。両方に習得記録がないUnitへ能力を補いません。能力のCommand／Event履歴も識別子・回復値・定義費用・チャージ残数を検証します。ログは後の開拓者消費・部隊統合後も残るので、過去の対象や部隊が現存することは要求しません。

版なしの保存は従来の未使用フィールドをそのまま保持します。新能力の状態・回数・履歴だけが版なしで残る部分保存は拒否します。保存読込は状態や回数を再初期化しません。

[互換検証](../tools/qa/save-ability-compat.mjs)は実際の前回ソースで生成した224保存と896継続Commandを比較します。9開始設定・4seed、研究・施設・攻城の旧版、開拓者、負傷しmanaを持つAIを含み、復元状態・JSON・AI判断・継続結果が一致します。全歴史的中間版・任意の手編集保存の保証ではありません。[結果](../assets/qa/save-ability-compat-2026-11-04.json)。

## 検証と残る範囲

[能力テスト](../tests/abilities.test.js)は33件。費用・対象・回復上限・同一Command再実行・手番／全体ターン境界・有限チャージ枯渇・生産購入・再編・不正保存・決定論を確認します。増援戦・都市争奪戦の2AI対局を各2seedで終了まで進め、各手番境界から同一再開を確認します。通常対局の長期的なバランス評価とは区別します。
