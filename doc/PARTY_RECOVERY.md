# 部隊の休養・回復と戦闘不能者の離脱

確認日: 2026-10-30（JST）。PR #7の54934b2から追加。[現行実装](CURRENT_IMPLEMENTATION.md)・[操作](../wiki/rules/recovery.md)・[検証](STATUS.md)。以下は暫定の現行規則で、目標仕様本文は変更しません。

## 共通条件と費用

新規開始の全モードは`partyRecoveryVersion: 1`を持ちます。自国手番のPLAYER_ACTION・開始処理済み・生存Unitがいるactive部隊が対象です。未終了、hasMoved/hasAttackedがfalse、移動力・攻撃回数が最大値であることが必要です。移動後、攻撃後、再編後、同じ手番の休養や離脱の連続実行はできません。反応を先に消費しただけなら、他条件を満たせば実行できます。

場所は自国領または未所有の非Voidセルです。同じセルか隣接セルに敵の生存軍事部隊、または防御が残る敵都市があれば拒否します。敵の民間部隊・待機兵・敗北記録はこの安全判定の対象外です。遠隔射程全域を安全地帯と判定するものではありません。生産・補充・合流・分割の既存条件は変えません。

成功時は移動力・攻撃回数・reactionChargesを0、activationStateをendedにします。Gold・人的資源・ID・RNGは消費しません。失敗時は元state・空eventsを返し、状態・資源・ログ・ID・RNGを保持します。通常の近接反撃と肩代わりは既存の規則で可能ですが、割り込みは反応0で行えません。

## RestParty

Payloadは`{ partyId }`です。少なくとも1体のHP>0・active・最大HP未満の構成員が必要です。命令を実行した時点ではHPを増やさず、Partyに`restOrder: { turn, location }`を保存します。

次の全王国一巡後の開始処理で、全Partyの休養を都市収入・生産・文化拡張より先に解決します。国の処理順によって回復可否が変わらないよう、同じ開始時点の領有・敵位置を使います。自国都市中心はHP+30、それ以外は+20をUnitごとの最大HPまで回復します。生存する戦士・弓兵・弩砲・開拓者が対象です。hp/currentHpを同時更新し、HP0・downed・shatteredを復活させません。

移動・領有変更などの成功Command後、敵軍の接近や敵領化で安全条件を失えば即座に予約を解除します。敵がその後離れても予約は戻りません。通常戦闘・護衛の肩代わりを含む正のHP損失は共通damage処理で休養を中止します。被害のない射撃失敗では中止しません。開始処理でも位置・前ターンの予約・生存・安全を再検証します。中止しても消費した手番は戻りません。

回復・中止後にrestOrderを削除します。手番交代だけでは回復せず、予約なしの自然HP回復もありません。morale・cohesion・statusEffects・有限charges・Ability状態は回復しません。通常の全体ターン開始による行動値とGuard容量の更新は従来どおりです。GAME_OVERでは予約を処理せず、終了時の記録を保持します。

イベントはPartyRestStarted（予定回復）、PartyRestCancelled（理由）、PartyRestCompleted（Unit別の回復量・結果HP）です。予測は公開HPと場所だけを読み、RNGを参照しません。表示する数値は、回復時まで中止条件が発生しなかった場合の値です。

## RemoveCasualties

Payloadは`{ partyId }`です。共通条件に加え、HP0の構成員を1体以上必要とします。該当する全員をParty.unitIds、formationから外し、離脱者を護衛側または対象側に含むguardOrdersを解除します。生存者の配置・HP・護衛残量・能力・士気・結束は保ちます。指揮者が戦闘不能なら生存者のcommandContribution降順、同値ID昇順で選び直します。戦闘時の指揮継承による士気低下を二重に適用しません。

Unit本体とKingdom.unitIdsは削除せず、離脱UnitのpartyIdだけnullにします。HP0・状態・位置はそのままで、以後部隊の移動には同行しません。PartyCasualtiesRemovedにunitIds・元のformation・位置・partyIdを記録します。Unitは一覧とセル詳細で「戦闘不能の記録」として確認でき、待機兵の駒・新規編成・補充候補には出しません。占有もしません。復活・搬送・捕虜・Lootは含みません。

離脱後に空く枠は次の全体ターン以降の補充・合流で利用できます。全員戦闘不能・defeated部隊は対象外で、敗北Partyの構成・配置・Unit記録を保持します。部隊全滅の勝敗、全都市支配の勝敗は変更しません。

新規版の王国軍事力に加算するUnit数はHP>0・active・非民間だけです。戦闘でのHP0直後と離脱後に派生値を再計算します。王国の登録一覧は履歴を含み続けます。AIの生存軍事Unit＋生産予約15体の上限は従来からHP0を除外しており、離脱で二重に人数を引きません。

## AIと画面

AIは合法な都市占領を最優先し、その後に自軍PartyをID順で確認します。各Partyでは安全な戦闘不能者の離脱、次に生存Unitのいずれかが最大HPの50%以下なら合法な休養を選びます。両命令は一手番を使うため、離脱と休養を同じ部隊へ同時には行いません。その後は従来の補充・都市出口・編成・攻撃・攻城・合流・接近・生産購入へ進みます。AIは休養場所を求めて撤退せず、現在地が合法な場合だけ選択します。

部隊選択後の「休養と戦闘不能者の離脱」にUnit別の予定回復、実行できない理由、休養待ちのターン、空く枠を表示します。ボタンで確定し、直近6件の休養・離脱ログを同欄へ表示します。AI行動一覧にも両命令を表示します。ロードで選択は解除しますが、予約・消費した行動・中止・離脱記録はGameStateに残ります。

## 保存互換

partyRecoveryVersionは都市攻城のcityDefenseVersionから独立しています。新規対局は1、既存保存は欠落を維持して旧規則を継続します。旧保存には休養・離脱・新AI判断・生存Unit限定の軍事力計算を追加しません。画面では新規開始で使える旨を説明します。

存在する不正な版・版なしの休養予約/休養離脱Command履歴は拒否します。restOrderは当ターン・開始処理済み・同じ位置・activeの生存負傷者・未移動未攻撃・行動終了・移動攻撃反応0・安全条件を検証します。nullや一部欠落を補完しません。離脱後の双方向所属・配置・指揮者・護衛参照は既存save-validationで検証します。復元そのものでは回復や資源収集を行いません。
