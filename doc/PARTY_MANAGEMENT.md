# 部隊の補充・合流・分割

確認日: 2026-10-30（JST）。PR #7の97285c1から追加。[現行実装](CURRENT_IMPLEMENTATION.md)・[操作](../wiki/rules/parties.md)・[AI](AI_SCENARIOS.md)。目標のPartyParameter集約、解散・任意離脱・手動Leader指定は後続です。

## 共通規則

再編は自国の手番のPLAYER_ACTIONで、生存Unitを含むactive部隊が対象です。関係する全部隊は未終了かつ移動力1以上が必要です。最大5体には所属中のHP0構成員も数えます。新規対局では別Commandで[戦闘不能者を離脱](PARTY_RECOVERY.md)させ、次の全体ターンから空いた枠を使えます。敵隣接中の禁止は今回追加しません。

成功すると関係する全部隊の移動力・攻撃回数・反応を0にし、activationStateをendedにします。途中移動後も条件を満たせば再編できますが、攻撃後や移動力切れでは実行できません。分割直後の合流など、同じターン中の再編連鎖はできません。次の全王国一巡後の開始処理で通常どおり回復します。通常の無料反撃は既存規則のままで、反応0が止めるのはInterceptです。

HP・Unitの能力・護衛容量残量・statusEffects・chargesを変更せず、資源・生産・RNGを動かしません。配置変更・護衛指定は既存どおり可能ですが、行動値や容量を回復しません。待機UnitからのCreatePartyも既存規則を維持します。

## 3つのCommand

- `ReinforceParty { partyId, unitIds }`: 同じセルにいる自国のHP>0・active・未所属Unitを重複なく選び、部隊へ追加します。開拓者も補充できます。元の配置を維持し、新Unitは前列左からの空き枠順に配置します。ID・位置・指揮者を維持しますが、指揮者が戦闘不能なら生存構成員から選び直します。イベントはPartyReinforcedです。
- `MergeParties { sourcePartyId, targetPartyId }`: 隣接する自国の異なる部隊を合流します。移動元には合流先地形の進入費（1または2）が必要です。合流先のID・位置・配置・生存指揮者を維持し、元部隊は削除します。移るUnitは元の枠が空いていれば保持し、埋まっていれば最初の空き枠へ置きます。両部隊内の護衛指示を保持します。士気・結束・最大移動力・最大攻撃回数は両者の小さい値を使い、合流で回復・強化しません。イベントはPartiesMergedです。
- `SplitParty { partyId, unitIds, location }`: 一部の構成員を隣接する非Void・活動部隊のいないセルへ移します。移動先地形費を払える移動力が必要です。残る部隊と新部隊の両方に生存Unitが必要で、戦闘不能者は生存者に同行できます。元部隊のIDを保ち、新部隊だけnextIds.partyを消費します。配置・士気・結束・最大行動値を引き継ぎ、部隊をまたぐ護衛指示だけを解除します。指揮者が抜けた側は生存者のcommandContribution降順、同値ID順で選び直します。新部隊は選択先頭が生存なら指揮者とし、戦闘不能なら同じ規則で選び直します。イベントはPartySplitです。

合流・分割で移動したUnitのpartyIdとlocationも更新します。敗北記録は占有せず、分割先と同じセルに履歴として存在できます。HP0の削除・復活や、敗北部隊の補充による復帰はありません。再編後も活動部隊数に応じた既存シナリオの勝敗規則を適用します。

## 画面とAI

部隊を選び「部隊の再編」で待機Unit、隣接する合流先、一部の構成員と分割先を選び、各実行ボタンで確定します。選ぶだけでは状態・乱数・ログを変更しません。分割先を選ぶと地図をそのセルへ合わせます。押せない理由をボタンの下に表示します。成功後は補充先・合流先・新分割部隊を選択します。ロードと部隊切替では編集中の選択を解除します。

増援AIは同じセルの非民間待機Unitを既存の戦闘部隊へ補充します。即時攻撃がなければ、隣接する軍事部隊を最大5体まで合流します。合流先は人数の多い順・ID順、合流元は少ない順・ID順で合法な組を選びます。民間を含む部隊はAIの合流対象外です。分割は人が指定する操作で、AIは自動分割しません。全操作を共通Commandと検証で処理します。

## 保存と検証

新しい永続フィールドはありません。既存の所属・位置・配置・指揮者・護衛・行動値・nextIdsを更新します。削除された合流元への現在参照を残しません。過去Command/Eventの合流元IDは履歴として保持します。失敗時は元state・空eventsで戻り、ID・RNG・資源・ログも変わりません。

旧保存の状態は維持します。この再編追加時点ではaiPolicy省略／tacticalの判断は変えませんでした。現在の新規対局は[休養・離脱の判断](PARTY_RECOVERY.md)も使います。既存のreinforcements方針には今回の補充・合流判断が加わるため、旧版と将来の行動列まで同一とは限りません。現行版で保存前後の再開は同一です。
